# 个人段落批注

## 使用

1. 打开讲义，点击「段落批注」，再点击正文段落或用 Tab 选中后按回车。
2. 输入批注并保存。右侧显示原文摘录、批注内容和管理按钮。
3. 通过左侧「我的批注」查看所有讲义的批注；可切换当前讲义，列表分页加载。
4. 点击「跳转段落」打开讲义并滚动、高亮和聚焦原段落；点击段落也会高亮关联批注卡片。
5. 编辑保存使用版本号防止覆盖其他设备的修改；删除需要确认，未保存的编辑在离开时会提醒。

## 绑定与权限

普通段落、标题、列表内段落和引用块内段落均可批注，代码块不作为正文段落。段落锚点由服务端解析 Markdown，保存讲义 ID、创建时的讲义版本、段落序号、内容摘要、重复数量和原文摘录；不改写 Markdown 正文。

唯一段落保持原文时，插入其他段落或移动位置仍可定位。重复段落在创建版本中通过序号区分；版本变化后不猜测重复段落的对应关系。段落改写、删除或匹配不唯一时，保留批注并标识定位失效。历史恢复后，唯一原文重新出现时可再次定位。

所有接口由登录会话决定用户 ID，拒绝客户端提交所有者。管理员和阅读用户只能查看、编辑、删除自己的批注，管理员无批注代管权限。无权限和不存在的批注统一返回 404。

讲义取消发布或进入回收站后，批注所有者仍能维护笔记内容，但阅读权限不足时不返回讲义标题、原文摘录或跳转位置；添加批注与打开正文继续执行讲义可见性检查。

## 接口与数据库

- `GET /api/annotations?lecture_id=1&offset=0&limit=100`：本人批注，讲义筛选可省略，每页最多 200 条。
- `POST /api/annotations`：`lecture_id`、`lecture_revision`、`paragraph_index`（从 0 开始）、`content`（非空，最多 10,000 字符）。
- `GET /api/annotations/{id}`：本人批注及当前段落定位；定位失效时 `paragraph_index` 为 null。
- `PUT /api/annotations/{id}`：`content`、`revision`；过期版本返回 409。
- `DELETE /api/annotations/{id}?revision=1`：永久删除本人批注；过期版本返回 409。

迁移 `0004_annotations.py` 新增 `annotations`，分别外键关联用户和讲义；为用户 ID 和讲义 ID 建索引。兼容旧库从 `0003` 升级和全新数据库初始化。旧客户端可忽略讲义渲染中新增的 `paragraphs` 字段。

## 备份边界

为避免管理员通过下载 ZIP 获取其他人的私人批注，应用资料备份不包含 `annotations`。当前数据库只要存在个人批注，应用内整库恢复就返回 409，且在写入文件或替换账户前停止，避免批注丢失或用户 ID 归属错配。服务器数据库备份必须包含此表；完整灾备恢复由服务器维护者处理。此版本尚未提供个人批注导出与导入。
