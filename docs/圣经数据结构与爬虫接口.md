# 圣经数据结构与爬虫接口

本文对应迁移 `0002` 和当前 `/api/bible` 接口，可作为后续采集程序的开发依据。此次提供目录、经文管理页面和单节写入接口；尚未实现网站爬虫。管理页不提供经文导入入口。

## 1. 数据层级与初始化

旧约、新约 → 书卷 → 章 → 节。旧约为 **39 卷**，新约为 **27 卷**，不是 39 章和 27 章。正文同时属于一个译本；不同译本可以在同一章使用不同的分节。

- 迁移初始化两约、66 卷、1,189 个章节目录，书卷代码及章节数沿用项目既有规范。
- 创世记 `Gen` 包含 50 章；第 1 章的参考节数记为 31，来自用户提供的信息。
- 其他章的参考节数暂为 `NULL`，表示未知，不能解释为 0 节或缺失整章。
- 迁移不会插入任何正式经文正文，也不会访问网站。
- 参考节数只用于页面核对，不作为各译本经节编号的硬性限制。当前写入接口允许 1～176 节。
- 两约、书卷、章节是固定目录，没有增删改接口。译本和经文正文是可维护的业务数据。

结构参考：[圣经目录](https://live.lxfyt.cn/shengjing/index.html)、[创世记章节目录](https://live.lxfyt.cn/shengjing/genesis_1.html)、[创世记第 1 章](https://live.lxfyt.cn/shengjing/genesis_1_1.html)。本次已读取总目录；两个创世记子页未能通过浏览工具取得，50 章／31 节采用用户给定信息，未据此推断其余章节的节数。

## 2. 表与字段说明

### `bible_testaments`：两约目录（新增）

- `code VARCHAR(2)`：主键。固定为 `OT`（旧约）、`NT`（新约）。必填。
- `name VARCHAR(20)`：中文名称，分别为“旧约”“新约”。必填。
- `position INT`：显示顺序，分别为 1、2；唯一、必填。

### `bible_books`：书卷目录（新增）

- `code VARCHAR(12)`：主键，规范书卷代码，例如 `Gen`、`1Sam`、`John`。必填。爬虫应使用此字段关联，不能使用网站英文路径代替。
- `testament_code VARCHAR(2)`：所属约，外键指向 `bible_testaments.code`。必填。
- `name VARCHAR(50)`：中文书卷名称，例如“创世记”。必填。
- `position INT`：全书顺序 1～66；唯一、必填。1～39 属于旧约，40～66 属于新约。
- `chapter_count INT`：该书卷的章节总数，例如创世记为 50。必填。

### `bible_chapters`：章节目录（新增）

- `book VARCHAR(12)`：所属书卷代码，外键指向 `bible_books.code`。必填。
- `number INT`：从 1 开始的章号。与 `book` 构成联合主键。例如 `('Gen', 1)`。
- `reference_verse_count INT NULL`：参考目录的节数；`NULL` 表示尚未收录参考数。不是已采集数，也不是所有译本的强制节数。
- `source VARCHAR(255)`：参考节数的来源地址；无来源时存空字符串。必填。此字段不代表经文正文来源。

### `translations`：译本（沿用）

- `id INT`：自增主键，供经文关联和 API 路径使用。
- `code VARCHAR(80)`：译本稳定标识，全库唯一；API 仅接受字母、数字、下划线、短横线。建议创建后固定不变。
- `name VARCHAR(150)`：译本显示名称，必填、不得空白。
- `language VARCHAR(30)`：语言标识，必填、不得空白；建议中文使用 `zh`，英文使用 `en`。
- `source TEXT`：正文来源说明或来源网址；API 最长 2,000 字符，默认空字符串。应填写实际译本及来源，不应仅根据网页语言猜测译本名称。
- `revision INT`：整个译本的修改版本号，初始为 1。每次单节写入、删除及既有整体替换流程都会递增，用于防止覆盖其他修改。

### `verses`：经文正文（沿用，增加章节外键）

- `id INT`：自增主键。采集程序不需要生成，也不能用它表达节号。
- `translation_id INT`：所属译本，外键指向 `translations.id`。必填。
- `book VARCHAR(12)`：规范书卷代码。必填。
- `chapter INT`：章号。必填。`(book, chapter)` 联合外键指向 `bible_chapters(book, number)`，防止不存在的章节进入数据库。
- `verse INT`：节号，从 1 开始。必填；API 限制为 1～176。
- `text TEXT`：该节正文，必填。API 接受 1～10,000 字符，剔除两端空白后不能为空。存普通文字，不保存网页 HTML。

唯一约束为 **`(translation_id, book, chapter, verse)`**。例如两个不同译本都可以保存 `Gen 1:1`，同一个译本不能保存两条 `Gen 1:1`。数据库使用 `utf8mb4` 保存中文和 emoji。数据库约束与 API 校验不同：MySQL 5.7 不应依赖 CHECK 来执行节号、正文长度等应用校验。

`stored_count` 仅为接口查询时计算的已录入行数，不是持久化字段。

## 3. 连接与认证

API 仍由本机 FastAPI 服务提供，仅监听 `127.0.0.1`。远程 MySQL 地址不是 HTTP API 地址。

- 桌面服务端口及应用密钥由 Electron 启动时生成，不可硬编码为固定端口或固定密钥。
- 独立采集集成可由操作者在启动本机后端时配置 `BIBLE_PORT`、`BIBLE_APP_KEY` 和数据目录／数据库连接。勿在另一个正式服务仍运行时启动同一资料库的重复服务。
- 每个 API 请求需要 `X-App-Key: <当前服务的应用密钥>`。
- `POST /api/login`，JSON 为 `{"username":"管理员用户名","password":"管理员密码"}`，返回 `token`；后续请求添加 `Authorization: Bearer <token>`。
- 使用既有管理员登录；阅读用户无法写入，首次登录要求修改密码的账户需要先在应用内完成改密。
- token 有效期为 12 小时，账户停用、改密或恢复备份也可能使 token 失效。
- 不要把密码、应用密钥或 token 提交到源码、写入采集结果或打印到日志。

下面所有路径都带 `/api`。示例中的译本 ID、revision 必须换成接口实际返回值。

## 4. 查询接口

### `GET /api/bible/catalog`

返回按顺序排列的两约及书卷，例如：

```json
[{"code":"OT","name":"旧约","books":[{"code":"Gen","name":"创世记","chapters":50,"position":1}]}]
```

以上仅展示部分内容，实际返回 2 约、66 卷。爬虫可用此接口获得全部规范代码，避免维护另一套不一致的目录。

### `GET /api/bible/books/Gen/chapters?translation_id=1`

返回该书卷所有章节：`number`、`reference_verse_count`、`source`、`stored_count`。省略 `translation_id` 时已录入数返回 0；要判断某译本采集进度必须传其 ID。

### `GET /api/translations`

返回译本的全部字段，包括 `id`、`code`、`revision`。采集开始前按稳定 `code` 查找已有译本，不应每次新建。

### `GET /api/bible/translations/1/Gen/1`

返回整章已保存的正文和该译本当前版本：

```json
{"revision":3,"verses":[{"verse":1,"text":"此处为采集后的正文"}]}
```

未录入章节返回空 `verses` 数组。经节按节号升序排列，不以空白正文伪造缺节记录。

### `GET /api/verses?translation_id=1&book=Gen&chapter=1&start=1&end=31`

既有引用阅读接口。返回逐节 `verse`、`text`、`missing`；未录入的节为 `text:null`、`missing:true`。该接口可用于采集结果抽查。

## 5. 写入接口（管理员）

### 新建空译本：`POST /api/translations`

```json
{"code":"my-source-zh","name":"经核实的译本名称","language":"zh","source":"https://live.lxfyt.cn/shengjing/index.html"}
```

成功返回 `{"id":1}`，版本初始为 1；代码已存在返回 409。创建后查询译本或章节以取得当前版本。当前页面和接口没有译本元信息修改或译本删除功能。

### 新增或更新单节：`PUT /api/bible/translations/1/Gen/1/1`

路径依次是 **译本 ID／书卷代码／章号／节号**。

```json
{"text":"采集并清理后的该节正文","revision":1}
```

成功返回 `{"revision":2}`。不存在则新增，存在则更新；返回的版本号用于下一次写入。同一译本的并行修改会发生版本冲突，建议采集程序顺序写入。即使正文未变化，调用 PUT 也会递增版本；采集程序应先比较文字，跳过相同内容。

### 删除单节：`DELETE /api/bible/translations/1/Gen/1/1?revision=2`

成功返回新版本号，如 `{"revision":3}`。这是永久删除该节正文，应只在明确需要纠正数据时使用。网页临时失败或本次未采集到某一节，不应自动删除数据库现有正文。

### 常见错误

- `401`：登录失效，需要重新认证。
- `403`：无管理员权限、应用密钥不匹配或账户仍需改密；按返回的 `detail` 排查。
- `404`：书卷、章节、译本或待删除经节不存在。
- `409`：译本代码重复或修改版本过期。重新读取数据并核对差异，不要直接用新版本号覆盖其他人的修改。
- `422`：输入不合法，例如正文全空白、超长、非法书卷章号／节号。
- `503`：数据库未连接。

## 6. 采集写入 Python 示例

示例只演示认证、定位译本、比较正文和单节写入，不包含网页抓取及 HTML 解析。环境变量由操作者设置，`BIBLE_API_BASE` 例如 `http://127.0.0.1:<实际端口>/api`。示例依赖 `httpx`。

```python
import os
import httpx

client = httpx.Client(
    base_url=os.environ['BIBLE_API_BASE'].rstrip('/') + '/',
    headers={'X-App-Key': os.environ['BIBLE_APP_KEY']},
    timeout=30,
)

def request(method, path, **kwargs):
    response = client.request(method, path, **kwargs)
    response.raise_for_status()
    return response.json()

session = request('POST', 'login', json={
    'username': os.environ['BIBLE_ADMIN_USER'],
    'password': os.environ['BIBLE_ADMIN_PASSWORD'],
})
client.headers['Authorization'] = 'Bearer ' + session['token']

code = 'my-source-zh'
translation = next((t for t in request('GET', 'translations')
                    if t['code'] == code), None)
if translation is None:
    tid = request('POST', 'translations', json={
        'code': code, 'name': '经核实的译本名称', 'language': 'zh',
        'source': 'https://live.lxfyt.cn/shengjing/index.html',
    })['id']
else:
    tid = translation['id']


def save_chapter(book, chapter, collected):
    # collected 是解析后 {节号: 纯文本}，例如 {1: text1, 2: text2}。
    path = f'bible/translations/{tid}/{book}/{chapter}'
    current = request('GET', path)
    revision = current['revision']
    existing = {v['verse']: v['text'] for v in current['verses']}
    for number, text in sorted(collected.items()):
        text = text.strip()
        if not text:
            raise ValueError(f'空正文：{book} {chapter}:{number}')
        if existing.get(number) == text:
            continue
        # 409 会抛异常并停止，由调用方重新读取核对；不盲目重试。
        revision = request('PUT', f'{path}/{number}', json={
            'text': text, 'revision': revision,
        })['revision']

# 在网站解析器完成后调用：save_chapter('Gen', 1, collected)
client.close()
```

单节写入各自是独立事务，不保证整章原子提交。断点续跑时重新读取整章，跳过已有相同正文。请求超时可能发生在服务端已提交之后，先查询结果再决定是否重试。采集器应自行保留网页来源、采集时间、错误及重试队列；当前 `verses` 没有逐节来源、采集时间或历史版本字段。

## 7. 直接写库的约定

优先调用上述 API，以复用正文校验、管理员权限和并发检测。若后续开发独立 SQL 写入程序，必须执行相同规则：

1. 使用 `utf8mb4`，以规范书卷代码匹配已经初始化的章节，不创建重复目录。
2. 在事务内锁定相应 `translations` 行（`SELECT ... FOR UPDATE`）。
3. 按四字段唯一键新增或更新 `verses`；校验章号、节号、正文及长度。
4. 修改正文时同步递增 `translations.revision`，否则管理页面无法发现变更，旧导入预览也不能正确失效。
5. 提交成功后更新采集进度；失败回滚。不要写入正式账户、讲义或会话表。
